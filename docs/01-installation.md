# 1. Установка

Этот документ — для ситуаций:

* настроить School AI на **новом Mac** (или после переустановки macOS);
* **обновить** существующую установку;
* перенести управление на **другой свой компьютер**.

Почти всё делает один скрипт — `deploy/install.sh`. Его можно запускать сколько
угодно раз: он проверяет, что уже сделано, и делает только недостающее.

---

## 1.1. Требования к серверу

* Mac на Apple Silicon (M1–M4), рекомендуется от 32 ГБ памяти
  (модель `qwen3:14b` занимает ~10 ГБ, embedding-модель ~4 ГБ);
* macOS 15 или новее;
* ~40 ГБ свободного места (модели + база);
* доступ в интернет на время установки (скачать пакеты и модели).

**Текущий сервер:** Mac Studio, Apple M4 Max (14 ядер CPU), 36 ГБ памяти,
macOS 27, hostname `school-ai`, адрес `192.168.2.101`, работает без монитора.
Ollama 0.35, PostgreSQL 17.11, pgvector 0.8.7, Python 3.13.

---

## 1.2. Подготовка Mac (один раз, руками)

Эти шаги меняют системные настройки, поэтому скрипт их не делает.

### Сеть и удалённый доступ

**Системные настройки → Основные → Общий доступ:**

* включить **Удалённый вход** (SSH);
* по желанию — **Общий экран** (Screen Sharing).

Задать имя компьютера, например `school-ai`.
Желательно закрепить за Mac постоянный IP-адрес в настройках роутера.

### Работа без монитора и после отключения питания

В Терминале на сервере:

```bash
sudo pmset -a sleep 0 disksleep 0 autorestart 1 womp 1
```

| Параметр | Значение |
|---|---|
| `sleep 0` | никогда не засыпать |
| `disksleep 0` | не останавливать диск |
| `autorestart 1` | включаться сам после отключения питания |
| `womp 1` | просыпаться по сети (Wake-on-LAN) |

Проверка: `pmset -g`.

> **FileVault.** Если FileVault включён, после перезагрузки Mac ждёт ввода
> пароля на экране и сервисы не стартуют. На этом сервере FileVault отключён
> осознанно. Если включаете — понадобится физический доступ после каждой
> перезагрузки.

### Homebrew

Homebrew — менеджер пакетов, через него ставятся Python, PostgreSQL и Ollama.
Устанавливается от администратора (не через `sudo`):

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

После установки выполните две команды, которые Homebrew покажет в конце
(добавляют `brew` в `PATH`).

## 1.3. SSH-ключ на вашем компьютере

Если ключа ещё нет:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/school-ai -C "school-ai"
```

```bash
ssh-copy-id -i ~/.ssh/school-ai.pub asemochkin@192.168.2.101
```

Проверка — должно войти без пароля:

```bash
ssh -i ~/.ssh/school-ai asemochkin@192.168.2.101
```

Если адрес сервера, имя администратора или ключ другие — поправьте
`deploy/config.sh`.

## 1.4. Установка

На вашем компьютере, в папке репозитория:

```bash
deploy/sync.sh
```

Что происходит:

1. Код репозитория копируется на сервер в `~/school-ai-src`.
2. На сервере запускается `sudo bash ~/school-ai-src/deploy/install.sh` —
   **введите пароль администратора сервера**, когда терминал попросит.

`install.sh` по шагам:

| Шаг | Что делает |
|---|---|
| 1 | ставит через Homebrew `python@3.13`, `python@3.12`, `postgresql@17`, `pgvector`, `ollama` (если их нет) |
| 2 | создаёт скрытого служебного пользователя `service` — от него работают все сервисы |
| 3 | создаёт `/opt/school-ai/{app,config,data,logs,models,open-webui}` с правильными правами |
| 4 | копирует код в `/opt/school-ai/app` (документы **не трогает**) |
| 5 | создаёт Python-окружение `/opt/school-ai/.venv`, ставит зависимости и команду `school-ai` |
| 6 | создаёт `/opt/school-ai/config/.env` со случайным паролем БД и ключом API (если их ещё нет) |
| 7 | запускает PostgreSQL как системный сервис, создаёт БД `school_ai`, роль `school_ai`, расширение `vector`; запрещает вход без пароля |
| 8 | запускает Ollama как системный сервис (только `127.0.0.1:11434`), скачивает модели |
| 9 | создаёт/обновляет таблицы |
| 10 | запускает страницу «Документы» и API (`8000`) и службу автоматической индексации |
| 11 | ставит Open WebUI (отдельное окружение на Python 3.12), создаёт `config/open-webui.env`, запускает сервис (порт `8080`) |
| 12 | только с `--reindex`: полная переиндексация (обычно индексирует служба) |

Первая установка занимает 20–40 минут (в основном — скачивание моделей ~13 ГБ
и установка Open WebUI).

Параметры (передаются через `sync.sh`):

```bash
deploy/sync.sh --reindex       # переиндексировать всё заново
deploy/sync.sh --no-models     # не проверять/не скачивать модели
deploy/sync.sh --upload-only   # только скопировать файлы на сервер
```

### Первый вход в Open WebUI — регистрация администратора

Сразу после установки Open WebUI доступен **только через SSH-туннель** —
чтобы никто в сети не успел зарегистрироваться первым.

1. На вашем компьютере: `deploy/tunnel.sh` — откроется `http://localhost:8080`.
2. Нажмите **Sign up / Регистрация** и создайте учётную запись.
   **Первый зарегистрированный пользователь становится администратором.**
3. Язык интерфейса: аватар → **Settings → General → Language → Русский**.
4. Откройте доступ из сети школы: `deploy/network.sh open` (см. `03-maintenance.md`, раздел 3.5).

Остальные сотрудники регистрируются сами, но попадают в статус «ожидает» —
администратор одобряет их в **Панель администратора → Пользователи**.

## 1.5. Проверка

На сервере:

```bash
school-ai check
```

Ожидаемый результат:

```text
✓ Ollama доступна (http://127.0.0.1:11434)
  ✓ модель qwen3:14b
  ✓ модель qwen3-embedding:4b
✓ PostgreSQL доступен, pgvector 0.8.7
  документов: 1, фрагментов: 799
```

Контрольные вопросы:

```bash
school-ai eval
```

```text
✓ 1. Что сказано в пункте 27.4?
...
Итог: 7/7
```

## 1.6. Обновление

Изменили код — та же команда:

```bash
deploy/sync.sh
```

Скрипт обновит код и перезапустит API, службу индексации и Open WebUI. Модели, база, документы, пользователи и чаты не пересоздаются.

Версия Open WebUI закреплена в `deploy/install.sh` (`OWUI_VERSION`). Чтобы
обновить Open WebUI — поменяйте номер версии, сделайте `deploy/backup.sh`,
затем `deploy/sync.sh`.

---

## 1.7. Перенос на другой Mac

1. Сделайте свежую резервную копию: `deploy/backup.sh` (документы окажутся в `local/data`).
2. Подготовьте новый Mac по разделу 1.2.
3. Поменяйте `SERVER_HOST` (и при необходимости `SERVER_USER`) в `deploy/config.sh`.
4. Добавьте SSH-ключ (раздел 1.3).
5. Установите систему: `deploy/sync.sh`.
6. Загрузите документы: `deploy/push-data.sh` — служба индексации обработает их сама.

База поиска будет построена заново из документов. Пользователей и чаты Open
WebUI, а также журнал вопросов можно восстановить из резервной копии
(см. `03-maintenance.md`, раздел 3.4).

## 1.8. Работа с другого своего компьютера

```bash
git clone <адрес репозитория> sk-ai
cd sk-ai
deploy/backup.sh         # скачать документы и базы с сервера в local/
```

Папка `local/` в git не хранится. Главная копия документов — на сервере,
поэтому на новом компьютере её достаточно скачать через `deploy/backup.sh`.
