# 2. Работа с документами

## 2.1. Куда класть файлы

**Главная копия документов — на сервере**, в `/opt/school-ai/data/`.
На вашем компьютере `local/data/` — её резервная копия (обновляется
`deploy/backup.sh`). Структура одинаковая:

```
/opt/school-ai/data/   (на компьютере: local/data/)
├── catalog.toml            ← необязательно: названия документов
├── documents/              ← НОРМАТИВНАЯ БАЗА (по ней отвечает система)
│   ├── regulations/            положения, порядки, регламенты
│   ├── school/                 внутренние документы школы
│   ├── instructions/           инструкции
│   ├── ib/myp/, ib/dp/         материалы IB
│   └── other/
└── reports/                ← ПРИМЕРЫ ОТЧЁТОВ (отдельная коллекция)
    ├── 2024-2025/
    └── 2025-2026/
```

* **Первая папка** (`documents` или `reports`) — это **коллекция**. По умолчанию
  вопросы ищутся только в `documents`. Примеры Progress Reports специально
  хранятся отдельно, чтобы не смешиваться с нормативными ответами.
* **Подпапка** (`regulations`, `ib/myp`, …) — **тип документа**. Можно создавать
  любые подпапки.

## 2.2. Добавить, изменить, удалить — страница «Документы»

Откройте страницу «Документы»:

* через туннель: `deploy/tunnel.sh` → `http://localhost:8000`;
* из сети школы (после `deploy/network.sh open`): `http://school-ai.local/documents/`.

Вход — той же учётной записью, что и в Open WebUI: если вы уже вошли в чат
на этом адресе, страница откроется сразу.

| Действие | Как |
|---|---|
| Загрузить | открыть папку → «Загрузить файлы» или перетащить файлы в окно |
| Новая редакция | загрузить файл с тем же именем → подтвердить замену |
| Создать папку | «Новая папка» |
| Переместить / переименовать | «Переместить» → ввести новый путь, например `documents/school/plan-2026.docx` |
| Удалить | «Удалить» — документ пропадёт и из базы знаний |
| Скачать | «Скачать» |

**Права:** загружать, перемещать и удалять могут **администраторы** Open WebUI;
обычные пользователи видят список и могут скачивать файлы.

**Статус** рядом с каждым файлом:

| Статус | Значение |
|---|---|
| ✓ в базе | проиндексирован: видно название и число фрагментов |
| ⏳ в очереди / индексируется | служба индексации работает с файлом (страница обновится сама) |
| ⚠ нет текста | текста не найдено — скорее всего, скан без OCR |
| ✗ ошибка | файл не удалось разобрать — текст ошибки под статусом |
| ⚠ (строка под статусом) | предупреждение, например «нет текстового слоя на страницах 3–5» |

### Как это работает

Служба `ru.school-ai.indexer` (команда `school-ai watch`) каждые 5 секунд
проверяет папку `/opt/school-ai/data`. Новый или изменённый файл она
индексирует, как только он перестанет меняться (загрузка закончилась), а
удалённый — убирает из базы. Поэтому неважно, как файл попал в папку:
через страницу, `deploy/push-data.sh` или напрямую на сервере.

Журнал службы: `/opt/school-ai/logs/indexer-error.log`.

### Много файлов сразу

Для массовой загрузки (или восстановления на новый сервер) удобнее
`deploy/push-data.sh`: положите файлы в `local/data/documents/...` на своём
компьютере и запустите скрипт. С флагом `--mirror` сервер станет точной копией
`local/data` (лишние файлы будут удалены — скрипт спросит подтверждение).

Система сама понимает, что изменилось (по контрольной сумме файла), и
обрабатывает только новые/изменённые файлы. Индексация «Положения о закупках»
(около 800 фрагментов) занимает ~1,5 минуты.

## 2.3. Поддерживаемые форматы

| Формат | Как разбирается | Качество структуры |
|---|---|---|
| **.docx** | абзацы, таблицы, стили заголовков, **автонумерация Word** | ★★★ лучший вариант |
| .doc, .rtf, .odt, .html | конвертируются в DOCX (LibreOffice, если установлен; иначе встроенный `textutil`) | ★★ — через `textutil` автонумерация теряется |
| **.pdf** | текстовый слой, номера страниц, заголовки по размеру шрифта, удаление колонтитулов | ★★ если номера пунктов набраны текстом |
| .txt, .md | абзацы; в Markdown `#` — заголовки | ★★ |
| .xlsx, .csv | каждая строка → «Колонка: значение; …», лист → раздел | для справочных таблиц |
| .pptx | слайд → раздел, текст, таблицы, заметки докладчика | ★ |

**Советы:**

* Если есть выбор — **загружайте DOCX**. В нём номера пунктов восстанавливаются
  точно так же, как их показывает Word.
* Старые `.doc` лучше один раз открыть в Word и **сохранить как .docx**.
  Либо установить LibreOffice на сервер: `brew install --cask libreoffice`.
* **Сканы PDF** (картинки без текста) система прочитать не может — при индексации
  будет предупреждение «Нет текстового слоя… нужен OCR». Такой PDF нужно
  распознать (например, в Adobe Acrobat или ABBYY FineReader) и загрузить заново.
* Номера пунктов в PDF/TXT распознаются, если стоят в начале абзаца:
  `1.`, `2.3.`, `4.1.2`, `Глава 2`, `Раздел II`, `Статья 5`, `IV.`

## 2.4. Проверить, как система «видит» документ

Перед загрузкой важного документа полезно посмотреть его структуру.
На сервере:

```bash
school-ai parse /opt/school-ai/data/documents/regulations/polozhenie.docx --grep 28
```

```text
Парсер: docx; блоков: 860; страниц: —
Разделов: 781 (с номером: 780); фрагментов: 799

  28 (numbered): Основания отклонения заявки.
    28.1 (numbered): ЗО отклоняет заявку участника закупки на следующих основаниях:
      28.1.1 (numbered): непредставление в составе заявки документов и сведений…
      ...
```

Если номера пунктов не распознались (`с номером: 0`), ответы будут без точных
ссылок на пункты — стоит найти DOCX-версию документа.

Локально (без сервера) то же самое можно сделать так:

```bash
uv venv -p 3.13 .venv && uv pip install -p .venv/bin/python -e .
.venv/bin/school-ai parse local/data/documents/school/файл.pdf
```

## 2.5. Названия документов — `catalog.toml`

Название документа попадает в ответ: «Положение о закупках…», п. 28.1.3.
Система определяет его сама (свойства файла → строка вида «Положение о…»
в начале → имя файла). Если получилось неудачно — задайте вручную в
`local/data/catalog.toml`:

```toml
["documents/regulations/polozhenie.docx"]
title = "Положение о закупках товаров, работ, услуг"
type = "regulation"
revision = "приказ от 16.01.2025 № 7-Пр"
```

Ключ — путь к файлу относительно `data/`. Загрузите `catalog.toml` в корень
папки данных через `deploy/push-data.sh` — служба индексации заметит изменение
и обновит названия.

Проверить названия: `school-ai docs`.

## 2.6. Контрольные вопросы

Файл `eval/questions.json` — набор вопросов с ожидаемыми пунктами.
После добавления важных документов дополните его:

```json
{
  "question": "В какой срок выставляются оценки в электронный журнал?",
  "expected_sections": ["2.1"]
},
{
  "question": "Какой ежегодный отпуск положен сотрудникам?",
  "expect_not_found": true
}
```

Запуск на сервере: `school-ai eval` (`-v` — показать ответы целиком).
Прогоняйте после каждого изменения кода или смены модели.
