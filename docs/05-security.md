# 5. Безопасность и работа без интернета

Главное требование: **внутренние документы, вопросы и ответы не должны попасть
в интернет.** Ниже — как это обеспечено и как проверить.

## 5.1. Куда ходят данные

```
Браузер сотрудника (сеть школы)
   │  HTTP только внутри локальной сети, порт 80
   ▼
Mac Studio ─────────────────────────────────────────────────────────────┐
│  Caddy :80 ──┬─► Open WebUI 127.0.0.1:8080 ──► School AI ──► Ollama    │
│              └─► «Документы» 127.0.0.1:8000     :8000        :11434    │
│        │                   │                                          │
│        └── webui.db        └── PostgreSQL :5432 (только 127.0.0.1)    │
│                                                                       │
│  Документы: /opt/school-ai/data                                       │
└───────────────────────────── ✗ интернет закрыт сетевым фильтром ──────┘
```

Модели работают на самом Mac Studio (Apple M4 Max, Metal). Ни один
компонент не отправляет текст документов, вопросы или ответы во внешние
сервисы.

## 5.2. Три уровня защиты

**1. Сетевые адреса.** Ollama, PostgreSQL, Open WebUI и School AI принимают
соединения только с самого компьютера (`127.0.0.1`). В локальную сеть (после
`deploy/network.sh open`) смотрит только Caddy на порту 80: он выводит чат и
страницу «Документы» — обе со входом по учётной записи. API `/v1` через Caddy
не доступен. Из интернета сервер
недоступен (школьный роутер не пробрасывает порты).

**2. Настройки сервисов.**

| Где | Что отключено |
|---|---|
| Ollama (`ru.school-ai.ollama.plist`) | `OLLAMA_NO_CLOUD=1` — облачные модели и веб-поиск ollama.com |
| Open WebUI (`config/open-webui.env`) | `OFFLINE_MODE` — проверка обновлений и загрузка моделей; веб-поиск; генерация картинок; Google Drive / OneDrive; внешние подключения пользователей; публикация в сообщество; телеметрия |
| School AI | обращается только к `127.0.0.1` (Ollama, PostgreSQL, Open WebUI) |

**3. Сетевой фильтр (гарантия).** Встроенный в macOS фильтр pf запрещает
**всем процессам пользователя `service`** — то есть Ollama, Open WebUI и
School AI — соединения за пределами компьютера и локальной сети. Даже если
кто-то по ошибке подключит внешнюю модель в настройках, запрос просто не
уйдёт. Остальная система (обновления macOS, Homebrew) работает как обычно.

```bash
deploy/firewall.sh on       # включить (сохраняется после перезагрузки)
deploy/firewall.sh test     # проверить
deploy/firewall.sh status
deploy/firewall.sh off      # выключить
```

Ожидаемый результат `test` при включённом фильтре:

```text
От имени service (так работают Ollama, Open WebUI, School AI):
  недоступно: https://ollama.com
  недоступно: https://huggingface.co
  недоступно: https://api.openai.com
  доступно:   http://127.0.0.1:11434/api/version
  доступно:   http://127.0.0.1:8080/health
  доступно:   http://127.0.0.1:8000/api/health
От имени администратора (сам Mac Studio):
  доступно:   https://ollama.com
```

`deploy/sync.sh` на время установки снимает фильтр (нужно скачать пакеты и
модели) и включает его обратно в конце — даже если установка прервалась.

**Защита от ошибок фильтра:**

* при каждом включении (и при загрузке сервера) фильтр проверяет сам себя:
  процессы `service` должны открывать и принимать соединения внутри
  компьютера. Если нет — фильтр снимается и выключается;
* `deploy/firewall.sh on` после включения проверяет «Документы» и Open WebUI
  **с вашего компьютера по сети** и только тогда закрепляет фильтр. Если
  проверка не прошла, сервер сам снимет фильтр через 90 секунд — пароль не нужен;
* `deploy/firewall.sh diagnose` — включает фильтр на 10 секунд, записывает
  проверки и счётчики правил в `/tmp/school-ai-firewall-diag.txt` на сервере
  и снимает фильтр. Для разбора проблем.

Как устроены правила (`deploy/pf-school-ai.conf`): трафик внутри компьютера
пропускается целиком; входящие подключения к портам 8000 и 8080 разрешены, и
ответы на них проходят автоматически; исходящие соединения процессов
`service` — только в частные сети, всё остальное запрещено.

## 5.3. Работа без интернета

**Да, всё работает без интернета.** Модели, база, документы и интерфейсы —
на Mac Studio. Интернет нужен только для:

| Действие | Когда |
|---|---|
| установка и обновление (`deploy/sync.sh`): Homebrew, Python-пакеты | при обновлениях |
| скачивание новой модели (`ollama pull`) | при смене модели |

Без интернета отвечать на вопросы, загружать и индексировать документы,
входить в Open WebUI можно как обычно. Включённый сетевой фильтр, по сути,
постоянно держит сервисы в режиме «без интернета» — то есть это проверено
каждый день работы.

Для доступа сотрудников нужна только **локальная сеть** школы.

## 5.4. Правила для администратора

1. **Не добавляйте внешние подключения** в Open WebUI
   (Панель администратора → Настройки → Подключения): только Ollama
   (`http://127.0.0.1:11434`) и School AI (`http://127.0.0.1:8000/v1`).
2. **Не скачивайте модели с суффиксом `-cloud`** — они работают на серверах
   ollama.com (при `OLLAMA_NO_CLOUD=1` они и так заблокированы).
3. **Не включайте** веб-поиск, генерацию изображений, интеграции с облаками.
4. Пароли и ключи — только в `/opt/school-ai/config/*.env` (права `600`).
   Не отправляйте их в чаты и не коммитьте в git.
5. Резервные копии (`deploy/backup.sh`) содержат документы и чаты — храните
   MacBook с включённым FileVault.
6. Доступ из интернета (HTTPS, VPN) — только осознанно и отдельной задачей.

## 5.5. Что остаётся вне этой защиты

* **Браузер сотрудника.** Если человек скопирует ответ в стороннюю нейросеть
  или мессенджер — это вопрос правил школы, а не техники.
* **Файлы, прикреплённые прямо в чат** (скрепка в Open WebUI), хранятся в
  `/opt/school-ai/open-webui/data` на Mac Studio — тоже локально.
* **Сама macOS** связывается с Apple (обновления, уведомления, время) —
  это не касается документов School AI.
* **SSH (22) и общий экран (5900)** открыты в локальной сети для
  администрирования; вход — по ключу / паролю администратора.
